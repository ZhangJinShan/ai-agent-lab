# 用户中心服务接口文档

> 版本:v2.3 | 维护人:平台组 | 最后更新:2026-09-15
> 本文档描述用户中心(user-center)对外提供的 HTTP 接口。所有接口走网关统一前缀 `/api/v1`,响应为 JSON,字符编码 UTF-8。

## 通用约定

- **传输协议**:全站 HTTPS,不接受 HTTP 明文请求;请求头需携带 `X-Request-Id`(调用方生成,用于链路追踪;未携带时服务端自动生成并在响应头返回)。
- **认证方式**:除登录接口外,其余接口均需在请求头携带 `Authorization: Bearer <accessToken>`。token 有效期 2 小时,过期返回 401(错误码 `USER_TOKEN_EXPIRED`)。
- **幂等性**:写接口(修改密码、用户信息修改)不保证幂等,调用方失败重试前应先查询确认状态,避免重复提交。
- **分页约定**:列表类接口统一使用 `page`(从 1 开始)和 `pageSize`(默认 20,最大 100)两个参数,响应中返回 `total` 总数。
- **错误响应**:统一格式 `{"code": "USER_xxx", "message": "...", "requestId": "..."}`,完整错误码见文末错误码表。

## 登录接口

账号密码登录,换取访问令牌。这是用户中心被调用最频繁的接口,也是爬虫撞库的主要目标。

- **路径**:`POST /api/v1/users/login`
- **限流**:单 IP **100 次/分钟**,超过返回 429
- **是否需要 token**:否

请求参数:

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| username | string | 是 | 用户名,长度 4~32,只允许字母数字下划线 |
| password | string | 是 | 密码,需前端 RSA 加密后传输(公钥见「前端接入指南」) |

响应示例:

```json
{
  "code": "USER_OK",
  "data": {
    "accessToken": "eyJhbGciOiJIUzI1NiJ9...",
    "refreshToken": "eyJhbGciOiJIUzI1NiJ9...",
    "expiresIn": 7200
  }
}
```

注意事项:

1. 连续 5 次密码错误,账号锁定 30 分钟(错误码 `USER_LOCKED`),锁定期间即使密码正确也拒绝登录。
2. 登录成功会触发「异地登录检测」,风控命中时额外返回 `riskLevel` 字段,前端需引导二次验证。
3. password 字段服务端日志全程脱敏,不要在接入方日志里打印原始密码。

## 令牌刷新接口

用 refreshToken 换新的 accessToken,避免用户频繁重新登录。

- **路径**:`POST /api/v1/users/token/refresh`
- **限流**:单用户 **60 次/分钟**
- **是否需要 token**:否(凭 refreshToken 调用)

请求参数:

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| refreshToken | string | 是 | 登录时下发的刷新令牌,有效期 7 天 |

注意事项:refreshToken **一次性使用**,刷新成功后旧的立即作废,响应返回新的 refreshToken;并发刷新以先到者为准,后到者返回 `USER_TOKEN_EXPIRED`,需重新登录。

## 用户信息查询接口

按用户 ID 查询基本信息。

- **路径**:`GET /api/v1/users/{userId}`
- **限流**:单用户 **300 次/分钟**
- **是否需要 token**:是

路径参数:`userId`(long,用户 ID)。查询他人信息需要 `user:read` 权限点,否则返回 403。

响应字段:

| 字段 | 类型 | 说明 |
|---|---|---|
| userId | long | 用户 ID |
| nickname | string | 昵称 |
| avatar | string | 头像 URL,7 天有效 |
| registerTime | string | 注册时间,ISO 8601 格式 |

注意**不返回**手机号、邮箱等敏感字段;敏感信息查询走独立的内部接口,不对外开放。头像 URL 带签名,过期后需重新查询获取,不要缓存超过 7 天。

## 用户信息修改接口

修改当前用户的昵称和头像。

- **路径**:`PUT /api/v1/users/{userId}`
- **限流**:单用户 **20 次/分钟**
- **是否需要 token**:是

请求参数:

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| nickname | string | 否 | 昵称,长度 2~20,敏感词过滤后入库 |
| avatar | string | 否 | 头像 URL,必须是文件服务域名下的地址 |

注意事项:两个参数至少传一个;昵称修改 30 天内最多 3 次(错误码 `USER_NICKNAME_LIMIT`);修改后用户信息缓存最长延迟 10 分钟生效(本地缓存 TTL 所致,详见配置说明文档)。

## 修改密码接口

修改当前登录用户的密码。

- **路径**:`POST /api/v1/users/password`
- **限流**:单用户 **5 次/小时**
- **是否需要 token**:是

请求参数:

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| oldPassword | string | 是 | 旧密码,RSA 加密 |
| newPassword | string | 是 | 新密码,长度 8~20,必须含大小写字母和数字 |

注意事项:修改成功后,该用户的**所有 accessToken 和 refreshToken 立即失效**,需重新登录;新密码不能与最近 3 次历史密码重复(错误码 `USER_PWD_REPEAT`)。

## 批量查询接口

按用户 ID 列表批量查询基本信息,供内部服务调用。

- **路径**:`POST /api/v1/users/batch`
- **限流**:单用户 **60 次/分钟**
- **是否需要 token**:是,且需要 `user:read` 权限点

请求参数:

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| userIds | array\<long\> | 是 | 用户 ID 列表,单次最多 100 个 |

响应为数组,顺序与入参一致;查不到的 ID 在数组中以 `null` 占位,**不报错**。单次超过 100 个直接返回 400(错误码 `USER_BATCH_LIMIT`)。

## 错误码表

| 错误码 | HTTP 状态 | 含义 | 处理建议 |
|---|---|---|---|
| USER_OK | 200 | 成功 | — |
| USER_LOCKED | 403 | 账号锁定(密码连续错误) | 提示用户 30 分钟后重试 |
| USER_TOKEN_EXPIRED | 401 | token 过期或已作废 | 走令牌刷新流程,失败则重新登录 |
| USER_PWD_REPEAT | 400 | 新密码与历史密码重复 | 提示用户更换密码 |
| USER_NICKNAME_LIMIT | 400 | 昵称修改次数超限 | 提示用户 30 天后再改 |
| USER_BATCH_LIMIT | 400 | 批量查询单次超 100 个 | 调用方拆批 |
| USER_NOT_FOUND | 404 | 用户不存在 | 检查 userId |
| USER_FORBIDDEN | 403 | 权限点不足 | 申请对应权限点 |
