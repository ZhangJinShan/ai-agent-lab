# 用户中心故障处理手册

> 面向:一线值班同学 | 升级路径:一线 → 平台组 oncall → 架构组
> 处理原则:先止血(止损优先于定位),再排查;所有操作记录到工单,禁止直接改生产数据。

## 登录大面积失败(网关 500)

**现象**:监控告警「登录成功率 < 50%」,用户反馈输对密码也登不进;网关日志大量 `POST /api/v1/users/login` 返回 500,错误栈指向 `JedisConnectionException`。

**常见原因**:Redis 连接池打满。登录依赖 Redis 缓存权限点和做密码错误计数,连接池默认 50;当有异常流量(如爬虫撞库)或连接未释放的发布事故时,池子会被耗尽,后续请求全部拿不到连接。

**处理步骤**:

1. 确认影响面:看 Grafana「登录成功率」面板和网关 QPS,判断是全量还是部分机器。
2. 止血:如果是刚发布引起,先回滚上一个版本;如果是流量异常,在网关层对 `/api/v1/users/login` 按 IP 限流(临时收紧到 20 次/分钟)。
3. 扩容连接池:调整配置 `redis.pool.max-active`(参考配置说明文档),灰度一台观察 5 分钟再全量。
4. 验证恢复:登录成功率回到 99% 以上,连续观察 15 分钟。
5. 复盘:输出故障报告,重点写清楚「连接池耗尽的诱因」和「为什么没有更早告警」。

## 接口响应缓慢(p99 飙升)

**现象**:告警「用户信息查询 p99 > 2s」(正常在 50ms 内),但错误率没有明显上升;用户反馈页面加载慢。

**常见原因**:MySQL 主从延迟。用户信息查询走读库,当大促导数据或批量任务压到主库时,从库回放延迟变大,查询全部变慢。次要原因:慢 SQL(未走索引的模糊查询)、GC 停顿。

**处理步骤**:

1. 先看数据库监控的「主从延迟」指标;延迟 > 1s 基本可定位为本原因。
2. 若是批量任务引起:暂停批量任务,延迟通常在几分钟内回落。
3. 若延迟不回落:检查从库机器负载,必要时切流到备用从库。
4. 若主从延迟正常:查看慢 SQL 日志,定位未走索引的查询,临时加索引或限流该接口。
5. 验证恢复:p99 回落到 100ms 以内,观察 15 分钟。
6. 复盘:评估读写分离的兜底策略(主库降级开关)。

## 短信验证码收不到

**现象**:客服反馈多位用户收不到登录/改密码的短信;短信平台控制台显示「发送成功」但用户手机无记录。

**常见原因**:第三方短信通道积压或被运营商风控拦截。单日发送量突增(如营销活动)会触发运营商的频控策略,消息进入延迟队列,表现为「发了但收不到」。

**处理步骤**:

1. 登录短信平台控制台,查看「发送状态」分布:如果大量「发送中」而非「成功」,是通道积压。
2. 切换备用短信通道(平台控制台 → 通道管理 → 启用备用通道)。
3. 如果是运营商风控:联系供应商报备签名和模板,申请解除频控。
4. 期间引导用户使用「语音验证码」作为替代方案。
5. 验证恢复:新发送的短信 30 秒内到达,连续观察 15 分钟。
6. 复盘:补充短信通道的多活配置和发送量分级告警。
