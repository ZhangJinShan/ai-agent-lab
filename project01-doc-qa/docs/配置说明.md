# 用户中心配置说明

> 配置中心:Nacos | 命名空间:prod | 分组:user-center | 最后更新:2026-09-18
> 修改配置后通过配置中心热生效,无需重启;标注「需重启」的除外。所有数值类配置修改前必须知会平台组 oncall,并在变更单里记录变更前后值。

## 超时配置

| 配置项 | 默认值 | 可调范围 | 说明 |
|---|---|---|---|
| http.connect-timeout | 5s | 2s~10s | 连接外部服务(短信、风控)的握手超时 |
| http.read-timeout | 30s | 5s~300s | 等待外部服务响应的读超时,超过即失败 |

注意事项:

1. 读超时的**上限是 300 秒**,调大超时会拖长线程占用,除非和架构组确认过,否则不建议调到范围之外。
2. 两个超时均支持秒(s)/毫秒(ms)两种单位写法,配置中心统一用秒。
3. 超时配置对所有出站 HTTP 调用生效,包括短信、风控、文件服务,不区分目标。

## Redis 连接池

| 配置项 | 默认值 | 说明 |
|---|---|---|
| redis.pool.max-active | 50 | 最大连接数,登录/鉴权链路共用 |
| redis.pool.max-idle | 20 | 最大空闲连接 |
| redis.pool.min-idle | 5 | 初始化连接数,需重启生效 |
| redis.pool.max-wait | 3s | 获取连接的最大等待时间,超时抛 JedisConnectionException |

注意事项:调大 `max-active` 前先确认 Redis 实例的 `maxclients` 余量,建议步长不超过 50 逐级调整并观察;调用方(网关、各业务服务)的连接数之和不能超过实例承载,具体实例规格相关参数由运维侧维护。历史上因连接池打满引发过 P0 故障(见故障手册),调整时务必对照该文档。

## 数据库连接池

| 配置项 | 默认值 | 说明 |
|---|---|---|
| db.pool.maximum-pool-size | 20 | HikariCP 最大连接数 |
| db.pool.minimum-idle | 5 | 最小空闲连接 |
| db.pool.connection-timeout | 3s | 获取连接超时 |
| db.pool.idle-timeout | 10m | 空闲连接回收时间 |
| db.pool.max-lifetime | 30m | 连接最大存活时间,需小于数据库侧 wait_timeout |

注意事项:数据库连接池调大之前必须评估 MySQL 实例的 `max_connections` 余量(所有应用共享);`max-lifetime` 不要大于数据库侧的 `wait_timeout`,否则会拿到已被服务端断开的连接报错。

## 缓存策略

| 配置项 | 默认值 | 说明 |
|---|---|---|
| cache.user-info.ttl | 10 分钟 | 用户基本信息本地缓存时长 |
| cache.perm.ttl | 5 分钟 | 权限点缓存时长 |
| cache.null-value.ttl | 60 秒 | 空值缓存时长(防缓存穿透) |
| cache.login-fail.lock-threshold | 5 | 连续密码错误锁定阈值 |
| cache.login-fail.lock-duration | 30 分钟 | 锁定时长,与接口文档一致 |

注意事项:用户信息缓存 TTL 调大会导致改昵称/头像后展示延迟,客服类投诉优先检查此项;权限缓存和登录锁定阈值不建议在大促期间修改。空值缓存时长影响「新注册用户立刻查不到自己」的窗口期,不建议超过 5 分钟。

## 接口限流配置

限流在网关层执行,数值与接口文档保持一致;下表为服务端兜底值,网关侧另有更严格的限流时以网关为准。

| 配置项 | 默认值 | 说明 |
|---|---|---|
| rate-limit.login | 100 次/分钟/IP | 登录接口 |
| rate-limit.token-refresh | 60 次/分钟/用户 | 令牌刷新接口 |
| rate-limit.user-query | 300 次/分钟/用户 | 用户信息查询接口 |
| rate-limit.user-update | 20 次/分钟/用户 | 用户信息修改接口 |
| rate-limit.password | 5 次/小时/用户 | 修改密码接口 |
| rate-limit.batch-query | 60 次/分钟/用户 | 批量查询接口 |

注意事项:大促期间网关会临时收紧登录限流(见故障手册),配置中心的兜底值保持不变;调整限流值属于对外行为变更,需产品和安全双签。

## 日志配置(需重启)

| 配置项 | 默认值 | 说明 |
|---|---|---|
| log.level | INFO | 可选 DEBUG/INFO/WARN;排查线上问题临时调 DEBUG 时,务必在 1 小时内调回 |
| log.retention-days | 15 | 日志保留天数,超过自动清理 |
| log.trace-header | X-Request-Id | 链路追踪请求头,不建议修改 |

注意事项:DEBUG 日志量约为 INFO 的 8 倍,磁盘水位超过 80% 时禁止开 DEBUG(曾因忘调回引发磁盘告警,见故障手册);日志中手机号、密码等敏感字段已脱敏输出,不要尝试关闭脱敏开关。

## 开关配置

| 配置项 | 默认值 | 说明 |
|---|---|---|
| switch.degrade-sms | false | 短信降级开关:开启后登录验证码固定返回成功(仅限演练和极端故障止血) |
| switch.risk-control | true | 风控开关:关闭后跳过异地登录检测(仅限风控服务故障时止血) |
| switch.read-only | false | 只读模式:开启后所有写接口返回 503(数据库故障时的止血手段) |

注意事项:三个开关都是**止血手段不是日常工具**,开启必须有对应故障工单;故障恢复后 24 小时内关闭并复盘。开关状态变更会记入审计日志。
